# Песочнца для агентов для OpenCode

Среда разработки на основе Docker для запуска и разработки с использованием OpenCode в изолированной контейнерной среде.

# Ролевая модель

Каждая роль обладает:
- Названием и псевдонимом (является синонимом названия, используется для исключения неоднозначности в документации)
- Типом (на основании которого определяется его место в иерархии)
- Зоной ответственности
- Набором функциональности

## Иерархия ролей

```
• Пользователь, "user"
└── • Аналитик проекта, "project-analyst"
    └── • Менеджер проекта, "project-manager"
        ├── • Go-разработчик, "go-developer"
        ├── • JavaScript-разработчик, "javascript-developer"
        ├── • Python-разработчик, "python-developer"
        └── • QA-инженер, "qa-engineer"
```

| Название роли          | Псевдоним роли         | Тип      |
|------------------------|------------------------|----------|
| Пользователь           | `user`                 | user     |
| Аналитик проекта       | `project-analyst`      | agent    |
| Менеджер проекта       | `project-manager`      | subagent |
| Go-разработчик         | `go-developer`         | subagent |
| JavaScript-разработчик | `javascript-developer` | subagent |
| Python-разработчик     | `python-developer`     | subagent |
| QA-инженер             | `qa-engineer`          | subagent |


### Пользователь `user`
- Является заказчиком любого изменения в системе
- Формирует первоначальное определение задачи

### Аналитик проекта `project-analyst`
- Получает первичные требования к созданию/доработке системы от `user`
- Интервьюирует `user` с целью получить всестороннее описание задачи
- Убеждается в полноте собранной информации
- По полученной от `user` информации создает и обновляет
  - документы с требованиями к продукту – Product Requirements Document (PRD) и/или
  - документы с требованиями к добавляемой функциональности – Feature Requirements (FR)
- Делегирует `project-manager` создание/доработку системы

### Менеджер проекта `project-manager`
- Является координатором, управляющим сложными техническими проектами и координирующий работу нескольких агентов искусственного интеллекта:
  - Go-разработчик
  - JavaScript-разработчик
  - Python-разработчик
  - QA-инженер
- В случае получения от `qa-engineer` отчёта с ошибкой о прохождении серии тестов системы делегирует задание на исправление ответственному за эту систему

### Go-разработчик `go-developer`
- Получает и анализирует на точность и полноту полученное от `project-manager` задание на создание/доработку системы
- Пишет готовый к работе код Go в соответствии с полученным заданием и лучшими практиками
- Обеспечивает качество, безопасность и производительность кода
- Обеспечивает соответствие кода принятому стилю
- Разрабатывает Unit-тесты, комплексные модульные и интеграционные тесты для сервисов и утилит, написанных на Go
- Актуализирует документацию в принятом формате и стиле по созданной/доработанной функциональности

### JavaScript-разработчик `javascript-developer`
- Получает и анализирует на точность и полноту полученное от `project-manager` задание на создание/доработку системы
- Пишет компоненты пользовательского интерфейса (React/Next.js/Vue), логику приложений, интеграции с API на JavaScript в соответствии с полученным заданием и лучшими практиками
- Обеспечивает качество, безопасность и производительность кода
- Обеспечивает соответствие кода принятому стилю
- Разрабатывает Unit-тесты, комплексные модульные и интеграционные тесты для 
- Актуализирует документацию в принятом формате и стиле по созданной/доработанной функциональности

### Python-разработчик `python-developer`
- Получает и анализирует на точность и полноту полученное от `project-manager` задание на создание/доработку системы
- Пишет готовый к работе код на Python (все уровни обслуживания – обработчики API, бизнес-логика, доступ к данным) для серверной части, ML, ETL и утилит в соответствии с полученным заданием и лучшими практиками
- Обеспечивает качество, безопасность и производительность кода
- Обеспечивает соответствие кода принятому стилю
- Разрабатывает Unit-тесты, комплексные модульные и интеграционные тесты для 
- Актуализирует документацию в принятом формате и стиле по созданной/доработанной функциональности

### QA-инженер `qa-engineer` 
- Комплексно тестирует систему, запуская интеграционные тесты и проверяя их выполнение
- В случае ошибки во время прохождения тестов формирует отчёт с явным указанием системы и контекста failed теста и передаёт его `project-manager`

## Рабочий процесс:

- `project-analyst` создает/обновляет документ с требованиями к продукту (PRD) или доработке системы (FR), делегирует его реализацию `project-manager`
  - `project-manager` получает от `project-analyst` документ с описанием создания/доработки системы (PRD или FR), создает и корректирует план разработки, делегирует его исполнение специализированным агентам, а после выполнения – проверяет
    - `go-developer` пишет весь код Go (серверная часть, микросервисы) и тесты на Go
    - `javascript-developer` пишет весь код на JavaScript (интерфейс) и тесты для интерфейса
    - `python-developer` пишет весь код на Python (серверная часть, ML, ETL, утилиты) и тесты на Python
    - `qa-engineer` запускает модульные и интеграционные тесты, проверяет их успешное прохождение, готовит отчёт для `project-analyst` (в случае ошибок)
  - `project-manager` отслеживает прогресс, отправляет задачу на доработку в случае ошибок при тестировании и создает/обновляет документацию (особенно важно после каждого успешного изменения)

**ВАЖНО**: Ни `project-analyst`, ни `project-manager` НИКОГДА не пишут код или тесты – только координируют и делегируют.

## Установка и разработка

### 1. Собрать окружение

```bash
make build
```

### 2. Настройка функции shell для легкого доступа

Для **fish** (as provided):
```fish
function oc
    docker run --rm -it \
        -e DEEPSEEK_API_KEY=$DEEPSEEK_API_KEY \
        -e PERPLEXITY_API_KEY=$PERPLEXITY_API_KEY \
        -v $(pwd):/workspace \
        opencode
end
```

Для **bash/zsh**:
```bash
oc() {
    docker run --rm -it \
        -e DEEPSEEK_API_KEY=$DEEPSEEK_API_KEY \
        -e PERPLEXITY_API_KEY=$PERPLEXITY_API_KEY \
        -v $(pwd):/workspace \
        opencode
}
```

### 3. Запустите OpenCode в песочнице

```bash
oc
```
