# Инструкция по созданию и валидации Product Requirements Document

## Введение
В режиме `NEW_PROJECT` задача аналитика — создать исчерпывающий, однозначный, компактный PRD для нового продукта на основе интервью с заказчиком. Документ должен позволять агентам (разработчикам, тестировщикам) работать без доступа к исходному коду.

# Этапы подготовки PRD через интервью (Discovery Interview)

## 1. Выявление проблемы (Problem Discovery)

- Сформулируйте основную проблему, которую должен решить продукт
- Определите целевую аудиторию и масштаб проблемы
- Изучите частоту возникновения проблемы, её последствия и текущие попытки решения
- Если возникли неясности — задайте уточняющие follow-up вопросы

## 2. Анализ целевых пользователей (User Discovery)

- Опишите user personas (роли, характеристики, опыт, устройства, контекст)
- Выявите основные цели пользователей и ограничения
- Уточните негативные (исключённые) персоны
- Документируйте возможности/ограничения освоения продукта

## 3. Исследование решения (Solution Discovery)

- Определите высокоуровневую концепцию решения
- Составьте список критических функций для MVP (3–7)
- Отобразите уникальные особенности и потенциальные расширения
- Выделите core value proposition и результаты, к которым стремится продукт

## 4. Технический контекст (Technical Context)

- Выясните тип приложения, потенциальный стек технологий, технические ограничения
- Определите ключевые интеграции, производительность, требования к безопасности, масштабируемости
- Уточните целевые платформы и бюджетные ограничения

## 5. Модели данных (Data Modeling)

- Определите основные сущности, их атрибуты и отношения
- Выясните источники и критические свойства данных, требования к сохранности и истории изменений

## 6. Пользовательские сценарии (User Flows)

- Подробно опишите 3–5 основных user flows: последовательность действий пользователя, альтернативные варианты, точки входа/выхода, исключительные ситуации

## 7. Бизнес-контекст (Business Context)

- Определите бизнес-цели, метрики успеха, целевой рынок, бизнес-модель, конкурентов, timeline, бюджет, основные риски

## Итеративный цикл уточнения и прогресса

- После каждого этапа: резюмируйте инсайты, выявите неясности, задайте follow-up вопросы
- Покажите прогресс по секциям PRD, выделите, что заполнено/что требует уточнения

# Валидация PRD перед финализацией

## Проверочные критерии по проблеме и решению:
- Проблема — реальна, значима, масштабируема и подтверждена общением с целевой аудиторией
- Решение — полностью/значительно закрывает проблему, технически и экономически реализуемо, пользователи готовы его использовать

## Критические вопросы для финальной валидации:
- Как проверили существование проблемы?
- С кем из аудитории обсуждали проблему?
- Какие альтернативы рассматривались?
- Почему выберут ваше решение?
- Какие риски угрожают успеху?
- Как определяется успех продукта (первые 3–6 месяцев)?

## Если возникли риски либо неясности — сформулируйте рекомендации и шаги по их устранению

# Чеклист готовности PRD.md

## ПОЛНОТА
- [ ] Все 13 секций заполнены
- [ ] Каждая функциональность содержит acceptance criteria
- [ ] Вся core-логика проекта полностью отображена

## ОТСУТСТВИЕ НЕОДНОЗНАЧНОСТИ
- [ ] Нет субъективных либо неясных терминов
- [ ] Все assumptions и ограничения явно указаны
- [ ] Все бизнес-правила полностью раскрыты

## ИСПОЛНИМОСТЬ
- [ ] Агент/разработчик может работать с PRD без дополнительных вопросов
- [ ] QA может тестировать с опорой на PRD

## КОНТЕКСТНАЯ ЭФФЕКТИВНОСТЬ
- [ ] Объем PRD в допустимых границах (5,000–8,000 токенов)
- [ ] Ключевые секции детализированы, второстепенные — кратко

## ДЛЯ `NEW_PROJECT` ДОПОЛНИТЕЛЬНО
- [ ] Выполнены все 7 этапов discovery-интервью
- [ ] Проведена валидация проблемы и решения
- [ ] Документированы assumptions и риски
- [ ] Определены success metrics и KPI
